# LendLoop take-home brief (verbatim requirements)
Build "LendLoop": a neighborhood tool-lending board with automated workflows. Neighbors list tools, request to borrow, get automated notifications/reminders via n8n.
Stack: Next.js (App Router), Clerk auth, Convex data+backend, n8n (Docker self-hosted), TypeScript.
Public page: company name LendLoop; tagline "Borrow what you need. Lend what you don't."; read-only list of available tools (name + category only, no owner details) from Convex; "Sign in to lend or borrow" button wired to Clerk.
Authenticated: list a tool (name, category [power tools, garden, kitchen, camping, etc.], condition, short description); request to borrow for a date range; approve/decline requests on own tools; mark loan returned. Views: all tools with availability status filterable by category; My listings; My requests; Incoming requests. Nice minimal layout.
Roles: admin can remove any listing, view all loans, mark a lender "Trusted Lender". user can create/edit/delete only own listings and act only on requests involving own tools or own borrowing. RBAC enforced in Convex functions, not only UI.
n8n: (1) Request notification: on borrow request create/status change, Convex calls n8n Webhook; workflow notifies relevant user (logged mock notification ok) using only needed fields. (2) Overdue reminders: scheduled daily, fetches overdue loans from a Convex HTTP endpoint, sends reminder to each borrower, writes reminder status back to Convex.
Security both directions: HMAC-signed payloads with shared secret, verified on receiving side; secrets in env vars and n8n credentials, never in code or exported workflow JSON; idempotent write-backs (no duplicate reminders on retry). Failures: retries + error workflow so failures are visible. Bonus: show recent automation activity per loan ("Reminder sent 2 days ago").
Deliverables: GitHub repo; exported n8n workflow JSON in repo; README with local setup (incl. n8n docker-compose), env vars, architecture, security & data-minimization decisions; short note on production changes.
Evaluated: code structure, security thinking, UX, integration design/reliability/error handling, documentation.
